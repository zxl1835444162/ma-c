# 使用说明

还原自 Windows 版 `app(1).exe`（v2.2.8）的 macOS/Windows 通用版。

## 这个工具在干什么

它用 Playwright 操控一个**专用的浏览器分身**，把本地写好的章节文件自动上传到小说平台。
发布流程完全走 CDP（Chrome DevTools Protocol）接管：

```
创建分身 → 生成启动器（带 --remote-debugging-port=42900 --user-data-dir=...）
启动分身 → 浏览器打开，你扫码登录
程序接管 → Playwright connect_over_cdp 连上这个浏览器
自动发布 → 打开写作后台、填标题、贴正文、点发布，逐章循环
```

所以「分身」不是多余步骤：每个笔名一个分身 = 一个独立的浏览器数据目录 + 独立端口，
多个账号互不串号，登录态也能长期保留。

```powershell
cd re\src\novel_publisher_mac
C:\Python310\python.exe app.py

# 首次需要装依赖
```

## 二、准备章节文件

程序只认 **`Chapter_001.md`、`Chapter_002.md`……** 这种命名，放在一个文件夹里。

文件内容格式（第一行是以 `# ` 开头的标题行）：

```markdown
# 第一章 天降奇缘
　　正文从这里开始……
　　（每章建议 1000 字以上，平台有下限）
@作者说：
　　这里可以写作者的话，可选。
```

手写太麻烦的话，「导入章节」能直接把一个 `.txt` 全文切成章节文件。
切分规则是识别这样的行（正则已从字节码还原）：

```
第X章：标题      也支持空格分隔：第X章 标题
支持中文数字与阿拉伯数字：第一章 / 第1章 / 第 12 章
行首可有 # 与空格：# 第3章：标题
```

注意两点（实测确认）：

1. 冒号或空格**后面必须有标题文字**，只写「第一章」不带标题的行不会被当章节头；
2. txt 文件带不带 UTF-8 BOM 都能正确切分（程序读取时会自动吞掉 BOM——
   Windows 记事本、部分写作软件默认会带 BOM，不加处理会让第一章丢失并整体错位）。

导入流程：`导入章节` → `浏览` 选 txt → `分解章节` → 预览列表 → `导入全部` 或 `追加导入`。
生成的目录在 txt 旁边（同名文件夹），也可以 `浏览` 指定保存目录。

## 三、第一次配置（按界面从上到下）

**① 浏览器地址/端口** — 点 `自动检测`。
程序会找本机 Chrome / Edge / Chromium（macOS 找 `/Applications`，Windows 查注册表），
找不到就手填浏览器可执行文件路径，或把 Playwright 内置 Chromium 的路径填进去。

**② 浏览器分身** — 填好「小说作者」（笔名）后点 `创建分身`。
- 生成启动器：Windows 是 `%APPDATA%\寒山小说发布工具\Shortcuts\<笔名>.lnk`，
  macOS 是 `.command`
- 分配调试端口（默认从 42900 起）并回填到「浏览器地址/端口」
- 笔名 → 端口 的映射存在同目录 `contrast.json`

`打开分身` 启动已创建的分身；`劫持分身` 把地址栏切回该笔名的端口号
（用于接管一个已经在跑的分身）。

**③ 登录** — 在刚打开的浏览器里扫码登录平台 → 回程序点 `登录(完成)`。
登录态保存到 `auth.json`，之后不用重复登录。

**④ 小说配置** — 小说标题（要和各平台上的完全一致）、笔名、小说文件夹（选步骤二的目录）。
`保存配置` 写入 `config.ini`。

## 四、发布

界面下半部分：

| 字段 | 说明 |
|---|---|
| 发布平台 | 番茄 / 起点 / 七猫 / 飞卢 / Q阅 / 纵横 / 微信 / 书旗 / 晋江 / 息壤 / 咪咕 |
| 发布模式 | 立刻发布 / 保存为草稿 / 定时发布 / 修改章节 |
| 每日定时发布时间 | 定时模式用，如 `06:00` |
| 间隔发布 | `周期/余数`，如 `1/0` = 每天都发；`7/0` = 每 7 天里的第 0 天发 |
| 每日更新章节数 | 每天发几章，`-1` 表示不限 |
| 每日更新字数 | 每天累计字数上限，`-1` 表示不限 |
| 上次更新日期 / 上次剩余章节 / 上次剩余字数 | 接着上次进度继续发，手动改或自动回填 |
| 后台执行 | 勾上则发布时保留浏览器窗口 |
| 格式索引 | 章节号补零（`001`）提交给平台 |
| 风险预检 | 发布前校对，出问题时暂停等你确认 |
| 发布章节范围 | 从第几章到第几章（默认接着上次更新日期算） |

点 **`开始发布`** 就跑整个过程。日志区实时显示每一步：打开后台、填标题、贴正文、点发布。
`Ctrl+P` 随时终止，`Ctrl+K` 跳过风险预检继续。

**最速开书**：弹出计划选择框，四组预设计划，如 `15+15*2+2*7` 表示
「先立刻发 1-15 章 → 再预发布 16-45 章（每日 15 章 × 2 天）→ 46-59 章（每日 2 章 × 7 天）」。
一次性连发，适合新书冲榜。

**扩展功能**：本地定时发布 / 自动签约 / 自动验证 / 短故事发布 / 短故事批量发布 /
书测 / 封测 / 全勤检查 / 发布进度自检 / 取消定时。

**短故事批量发布**：把统一格式的短故事 `txt` 放进程序目录下的 `短篇直出` 文件夹，
程序逐篇读取并发布（番茄平台限制一次最多 10 篇）。

## 七、文件放哪儿

```
Windows:  %APPDATA%\寒山小说发布工具\
macOS:    ~/Library/Application Support/寒山小说发布工具/
├── config.ini          界面与小说配置（保存配置写出）
├── auth.json           登录态（Playwright storage_state）
├── 签约信息.txt         自动签约用的作者信息
├── Shortcuts/
│   ├── contrast.json   笔名 → 调试端口
│   ├── <笔名>.lnk / .command   分身启动器
├── 42900/              分身专属浏览器数据目录（每个端口一个）
└── login_profile/      登录流程用的临时 profile
```

程序目录不会写入任何数据；首次运行会自动把旧的 `config.ini`、`auth.json` 迁进来。

## 八、常见问题

**日志报「未找到登录状态文件 auth.json」** — 还没走登录流程，先 `打开分身` 扫码，
再点 `登录(完成)`。

**「未找到该账号的分身」** — 笔名和创建分身时填的不一致，或者换了笔名没重新创建。

**发布时浏览器没反应 / 端口连不上** — 分身浏览器没启动，或那个端口被占用。
先 `打开分身`，再确认 `浏览器地址/端口` 一栏是纯数字端口号。

**「章节范围必须是有效的整数」** — 发布章节范围里有非数字内容。

**每章内容太少被平台拒绝** — 平台对正文有字数下限（一般 1000 字），补充后再发。

**macOS 首次打开 .app 提示损坏/无法验证** — 本机自测执行
`xattr -dr com.apple.quarantine 寒山小说发布工具.app`；对外分发需要开发者签名。
